# Техническое задание

Консольное приложение на C# принимает текст пользователя, передаёт его агенту на LangChain и выполняет выбранный агентом метод отдельного HTTP API.

## 1. Назначение

Пользователь описывает действие обычным текстом. Приложение определяет, какой метод API нужно вызвать, вызывает его и показывает результат в консоли.

Предметная область — учёт физических лиц. Единственный зафиксированный в описании пример: изменение данных физлица (`UpdatePerson`) и сообщение вида «Готово. Данные физлица изменены».

## 2. Состав системы

Система состоит из двух отдельных приложений.

1. Консольное приложение на C#. В нём работает агент на LangChain.
2. HTTP API со Swagger. Это Minimal API с фиксированным набором методов. Оно не входит в состав агента и не генерируется моделью.

Локальная модель поднимается через Ollama. Адрес по умолчанию: `http://localhost:11434`. API-ключ не используется.

## 3. Сценарий работы

1. При старте консольное приложение запрашивает текст.
2. Пользователь вводит текст.
3. Приложение проверяет длину текста. Допустимо не больше 500 символов.
4. Текст передаётся агенту.
5. Агент выбирает один инструмент из фиксированного набора и возвращает JSON с именем метода и аргументами.
6. Консольное приложение разбирает JSON и отправляет HTTP-запрос в API.
7. API возвращает ответ в формате JSON.
8. Консольное приложение показывает человеку результат, исходя из статуса ответа.

## 4. Контракт ответа агента

Агент возвращает JSON вида:

```json
{
  "name": "UpdatePerson",
  "args": { "id": 45 }
}
```

- `name` — имя выбранного метода API.
- `args` — аргументы этого метода.

Имя должно совпадать с одним из методов API. Произвольные имена и вызовы вне этого набора недопустимы.

## 5. Ограничения

- Ввод длиннее 500 символов не передаётся агенту. Пользователь получает сообщение о превышении лимита.
- Модель локальная, Ollama, `http://localhost:11434`.
- Набор методов API задаётся заранее и не меняется агентом во время работы.
- Консольное приложение только разбирает JSON агента и вызывает соответствующий метод. Выбор метода делает агент.

## 6. Результат для пользователя

Ответ API не печатается как сырой JSON. Консоль показывает короткое сообщение по статусу ответа. Для успешного изменения физлица: «Готово. Данные физлица изменены».

## 7. Проверка после реализации

После реализации нужно описать архитектуру текстом и проверить, что диаграмма Mermaid совпадает с этим описанием и с фактической работой приложения.
